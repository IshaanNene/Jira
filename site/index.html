Security

Your data stays yours.
The database enforces it.

Isolation

Row-level security

Every table that holds workspace data is filtered by Postgres itself. A bug in an API can't read another team's issues.

Identity

Tenant from a signed token

Which workspace a request belongs to comes from a signed token. It never comes from anything the browser can change.

Sign-in

SSO, SCIM, passkeys

OpenID Connect or SAML, SCIM provisioning of people and groups, passkeys, and two-step verification that admins can require.

-- Applied to every workspace table. The app sets the tenant from the signed token.
ALTER TABLE issues FORCE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON issues
  USING (tenant_id = app_tenant_id())
  WITH CHECK (tenant_id = app_tenant_id());

Questions

Before you ask.

Can we move from another tracker?
Meridian has the same building blocks as the big trackers: epics, stories, tasks, bugs and sub-tasks, custom fields, workflows, Scrum and Kanban boards, and a query language. Your team won't have to unlearn anything.
Where does our data live?
On Meridian's hosted service, in Postgres, with every workspace isolated by row-level security. Enterprise customers can also run Meridian on their own Kubernetes cluster with the provided Helm chart and Terraform.
What happens when we pass 10 people on Free?
Nothing breaks and nothing is deleted. You'll be asked to move to Team to add more people. Everything you've built stays where it is.
Do boards stay fast on big projects?
Boards read from a local copy of each project's cards that issue events keep up to date. That means a board loads from one place instead of asking the issue service every time. A board shows up to 5,000 cards.
Can we connect Slack, GitHub or our own tools?
Yes. Outgoing webhooks are signed, so you can check they came from Meridian. A webhook can post to a Slack channel. Commits and pull requests that mention an issue key appear on that issue. Personal API tokens cover scripts.
